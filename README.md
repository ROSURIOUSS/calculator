# FICSIT Ops — отдельная программа для Satisfactory

**Это внешняя программа для Windows, не мод.** Она не встраивается в игру, не изменяет её файлы и не читает сохранения.

В проекте есть:

- **Панель управления автопилотом** (`ficsit_ops.py`) — обычное окно Windows для настройки цели, запуска проверки экрана и остановки агента.
- **Планировщик фабрики** (`index.html`) — открывается из панели в браузере; считает базовые производственные цепочки и копирует план как миссию для автопилота.
- **Экспериментальный автопилот** (`pilot.py`) — видит игру через скриншоты и может отправлять короткие нажатия клавиш/мыши.

## Собрать Windows-программу `.exe`

Сборка выполняется **на Windows**. В этой рабочей среде Linux, поэтому готовый Windows `.exe` здесь собрать и проверить нельзя; вместо этого добавлен сборочный файл.

1. На Windows установи Python 3.11+ и Ollama. Для локальной vision-модели выполни:

   ```powershell
   ollama pull qwen2.5vl:7b
   ```

2. В корне папки проекта запусти двойным щелчком `build_windows.bat`.
3. После успешной сборки готовая программа появится в `dist\FicsitOps.exe`.
4. Запускай `FicsitOps.exe`. Самой программе Python уже не потребуется; Ollama с моделью остаётся отдельной зависимостью.

Сборка скачивает пакеты Python и PyInstaller из PyPI. Если Windows SmartScreen покажет предупреждение для самостоятельно собранного приложения, проверь, что запускаешь именно файл из папки `dist` этого проекта.

## Как пользоваться программой

1. Открой `FicsitOps.exe` и загрузи нужное сохранение Satisfactory.
2. В поле миссии оставь стандартную цель или вставь текст из планировщика фабрики.
3. Нажми **«Открыть планировщик фабрики»**, выбери продукт и выпуск. Кнопка «В миссию автопилота» копирует расчёт; вернись в программу и вставь его в поле миссии.
4. Сначала выбери **«Проверка — только анализ экрана»**. Открой игру за пять секунд после старта, чтобы программа увидела нужное окно. В этом режиме нажатий нет.
5. Только после проверки включай **«Управление клавишами и мышью»**. Программа отдельно попросит подтверждение; сохранись и оставайся рядом с компьютером.

Остановить автопилот можно кнопкой **«Остановить»**, клавишами F8/Esc или аварийно переместив курсор в верхний левый угол. Кнопка остановки прерывает цикл после текущего запроса к vision-модели; в течение этого запроса новое игровое действие не отправляется.

## Vision-модель и приватность

По умолчанию программа обращается к локальному Ollama по адресу `http://127.0.0.1:11434/v1` с моделью `qwen2.5vl:7b`. Изображения экрана остаются на компьютере, если используешь локальную модель. Если введёшь удалённый API endpoint, снимки экрана будут передаваться его провайдеру. API key вводится только в окно программы и не сохраняется в файле настроек. Для вставки поддерживаются Ctrl+V, Shift+Insert, меню по правому клику и кнопка «Вставить».

Для удалённого OpenAI-совместимого endpoint укажи его адрес, точный ID модели и API key в панели. Например, для Gemini API совместимый endpoint — `https://generativelanguage.googleapis.com/v1beta/openai`. Название «Авто / Gemini 3 models» из приложения Gemini не является API model ID; нужен идентификатор модели из Google AI Studio. Подписка Gemini Premium не гарантирует API-доступ или бесплатный API-лимит. Endpoint должен поддерживать изображения и `/chat/completions`.

## Планировщик фабрики

Планировщик можно открыть отдельно, открыв `index.html`. Он умеет искать продукты, принимать десятичную запятую (например, `2,5` ед./мин), считать рецептурную цепочку, машины, ориентировочную мощность и сырьё.

В `app.js` находятся стартовые базовые рецепты. Альтернативные рецепты, добывающие машины, вода, жидкости, побочные продукты и расход электроэнергии на добычу/генерацию пока не включены. Поэтому результат — базовая оценка, а не полный симулятор фабрики. Расчёт мощности производственных зданий использует приближённую кривую underclock (`clock^1.321928`).

## Ограничения автопилота

Автопилот — экспериментальная система «скриншот → vision-модель → короткое действие», а не гарантированно автономный игрок. Он может неверно прочитать интерфейс, тратить ресурсы или не суметь выполнить задачу. По умолчанию он должен сохранять существующие постройки и просить вмешательство при неопределённости. Сначала используй режим проверки, затем небольшие лимиты шагов и наблюдай за игрой.

Для разработки можно запустить панель из исходников командой `py ficsit_ops.py`, а CLI-автопилот — `py pilot.py --dry-run --max-steps 3`.
